============================================
Comprehensive Cardano Glossary
============================================
Blockchain Fundamentals
- UTxO: Unspent Transaction Output model where coins are outputs that can be spent once.
- eUTxO: Extended UTxO; adds data and scripts to UTxOs enabling smart contracts.
- Stake pool: Node that produces blocks; users delegate stake to pools.
- Delegation: Assigning stake to a pool to earn rewards.
- Epoch: Period (~5 days) used for staking/rewards/parameters.
- Slot: Smallest scheduling unit within an epoch for block production.
- Ada: Native currency of Cardano.
- Lovelace: Smallest unit of Ada (1 Ada = 1,000,000 Lovelace).
- Native tokens: On-ledger assets minted under policies without requiring smart contracts.

Smart Contract Terms
- Plutus: Haskell-based smart contract framework for Cardano.
- Aiken: Modern functional language + toolchain for Cardano smart contracts.
- OpShin: Python-flavored smart contracts compiled to Plutus Core.
- Helios: Lightweight, browser-friendly language compiling to Plutus Core.
- Marlowe: DSL and runtime for financial contracts; includes Playground.
- Datum: On-chain data attached to outputs consumed by validators.
- Redeemer: Input data provided to validators when spending outputs.
- Validator: On-chain script that authorizes spending of UTxOs.
- Minting policy: Script constraining mint/burn of native tokens.
- Plutus Core: Low-level IR executed by the ledger.

Developer Standards (CIPs)
- CIP-25: Standard for NFT metadata.
- CIP-30: Wallet–dApp Web Bridge providing the connector interface.
- CIP-54: Smart NFT specifications.
- CIP-68: Reference inputs metadata standard enabling mutable data patterns.

Cardano-Specific
- Hard fork combinator: Seamless protocol upgrades combining eras without chain restarts.
- Ouroboros: Proof-of-stake consensus family used by Cardano.
- Hydra: L2 isomorphic state channels for high throughput/low latency.
- Catalyst: Community funding/governance program.

Development Tools
- Serialization library: cardano-serialization-lib (multi-language, WASM bindings).
- Address types: Byron (legacy), Shelley (bech32-era and later formats).
- Transaction building: Constructing inputs/outputs, scripts, datums, fees, and witnesses.
- Off-chain code: Client/backend logic coordinating UTxOs and on-chain validators.

NFT & Token Terms
- Policy ID: Hash identifying a minting policy.
- Asset name: UTF-8/bytes label of a token under a policy.
- Minting/Burning: Creation/destruction of tokens per policy.
- Token registry: CF-managed metadata service for tokens.
- Metadata standards: CIP-25/68 for NFTs and datum-linked metadata.

DeFi Terms
- DEX: Decentralized exchange.
- AMM: Automated market maker model for swaps/liquidity.
- Liquidity pool: Token pair reserves backing AMM pricing.
- Yield farming: Incentivized liquidity/provision strategies.
- Staking: Delegating ADA to pools for rewards.
- Orderbook: Matching engine model alternative to AMM.
- Swap: Exchange operation between assets.

Wallet & Identity
- Seed phrase/Recovery phrase: Mnemonic used to derive keys; store securely offline.
- Hardware wallet/Software wallet: Key custody modality; hardware isolates keys.
- CIP-30 connector: Browser wallet interface enabling dApp access.
- Handle (naming): ADA Handle NFT alias resolving to addresses.
